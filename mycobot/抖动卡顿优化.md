# mycobot 280 轨迹抖动/卡顿优化方法

> 记录 MoveIt 2 + 真机执行时轨迹抖动、卡顿的排查与优化方案。
> 按"收益从大到小"排列，建议从 Tier 1 开始改。

---

## 现状：当前每一层的瓶颈

按"卡顿/抖动"出现概率从高到低排：

### 1. 硬件接口层 — `cmd_publish_rate=20 Hz`（最严重）

[`mycobot280_moveit2_control/src/mycobot280_hardware_interface.cpp:110-120`](mycobot280_moveit2_control/src/mycobot280_hardware_interface.cpp#L110)

```cpp
const auto rate_str = get_param("cmd_publish_rate", "20.0");
```

[`mycobot280_moveit2_control/include/.../mycobot280_hardware_interface.hpp:113`](mycobot280_moveit2_control/include/mycobot280_moveit2_control/mycobot280_hardware_interface.hpp#L113)
注释说 `default 50.0`，但代码里 fallback 是 **20 Hz**，且 yaml 里没显式设置 → 实际就是 20 Hz。

- ros2_control `update_rate=100 Hz` 算出的轨迹点
- 但 hardware interface 每 **50 ms** 才把命令发到 Python driver
- → trajectory 中一半的中间点被丢弃，机械臂每 50 ms "跳"一次 → **卡顿/抖动**

### 2. Python driver 层 — `send_angles` 非流式

[`mycobot280_moveit2_control/src/mycobot_driver_node.py`](mycobot280_moveit2_control/src/mycobot_driver_node.py)
用 `pymycobot.send_angles()`，每次是**独立段运动**（固件按速度=30 完成本段后停下）。
20 Hz 发命令 → 机械臂每段之间会被打断/重启 → 段间停顿感明显。

### 3. 关节限速 — 用满 100%

[`mycobot_moveit_config/config/mycobot_280/joint_limits.yaml:1-2`](mycobot_moveit_config/config/mycobot_280/joint_limits.yaml#L1)

```yaml
default_velocity_scaling_factor: 1.0
default_acceleration_scaling_factor: 1.0
```

`max_acceleration: 5.0 rad/s²` 已经偏高（~286°/s²），再 ×1.0 → 急加速急减速 → 抖。

### 4. 没有 jerk 限制

[`mycobot_moveit_config/config/mycobot_280/joint_limits.yaml:9`](mycobot_moveit_config/config/mycobot_280/joint_limits.yaml#L9)
每个关节都是：

```yaml
has_jerk_limits: false
max_jerk: 6.0
```

→ 加速度可以瞬间跳变 → 物理上的"抖"。

### 5. 没有 Ruckig 后处理

[`mycobot_moveit_config/config/ompl_planning.yaml:6-9`](mycobot_moveit_config/config/ompl_planning.yaml#L6)

```yaml
response_adapters:
  - default_planning_response_adapters/AddTimeOptimalParameterization
  - default_planning_response_adapters/ValidateSolution
  - default_planning_response_adapters/DisplayMotionPath
```

只有 TOTG 时间最优化参数化（理论最优但允许加速度瞬时跳变），
没用 Ruckig 做 jerk 受限平滑。

### 6. 控制器容差较大

[`mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml:49-52`](mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml#L49)

```yaml
goal:
  - 0.05  # 0.05 rad (~2.9 deg) per joint
path:
  - 0.05
```

接近目标时 2.9° 的容差会出现"突然认为到位了"的顿挫。

## Tier 1 — 立竿见影（改 yaml 参数，无需重编译 C++）

### (a) 提高 cmd_publish_rate

在 [`mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml`](mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml)
的 `controller_manager` 同级或 URDF `<ros2_control>` 块中加：

```yaml
mycobot280_hardware_interface:
  ros__parameters:
    cmd_publish_rate: 50.0   # 20 → 50，匹配 update_rate 的一半（python driver 顶天能处理 100Hz）
```

### (b) 降速 + 启用 jerk 限制

[`mycobot_moveit_config/config/mycobot_280/joint_limits.yaml:1-2`](mycobot_moveit_config/config/mycobot_280/joint_limits.yaml#L1)：

```yaml
default_velocity_scaling_factor: 1.0        # 1.0 → 0.4
default_acceleration_scaling_factor: 1.0     # 1.0 → 0.4
```

每个关节的 jerk（复制到所有 6 个关节）：

```yaml
    has_jerk_limits: true        # false → true
    max_jerk: 20.0               # rad/s³（典型 10~40）
```

### (c) 加 Ruckig 平滑

[`mycobot_moveit_config/config/ompl_planning.yaml:6-9`](mycobot_moveit_config/config/ompl_planning.yaml#L6)
在 response_adapters 前面插入 Ruckig（在 TOTG 之后做 jerk-limited 重定时）：

```yaml
response_adapters:
  - default_planning_response_adapters/AddTimeOptimalParameterization
  - default_planning_response_adapters/AddRuckigTrajectorySmoothing   # ← 新增
  - default_planning_response_adapters/ValidateSolution
  - default_planning_response_adapters/DisplayMotionPath
```

## Tier 2 — 进一步打磨

### (d) 收紧 controller tolerance

[`mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml:49-52`](mycobot280_moveit2_control/config/mycobot_280_real_controllers.yaml#L49)：

```yaml
    goal:
      - 0.02   # 0.05 → 0.02 rad (~1.1°)
    path:
      - 0.02
```

### (e) 提高 controller `action_monitor_rate`

20 Hz 监控执行进度太低，到点检测延迟大：

```yaml
    action_monitor_rate: 50.0   # 20 → 50
```

---

## Tier 3 — 架构层（如果上面还不够）

### (f) 改 Python driver 用流式接口

`pymycobot` 有 `write_angles`（直接发关节角，不等本段完成），
或更底层的 `send_angle` 单关节流式发送。
把 driver 的 `send_angles(angles, speed=30)` 换成更频繁的 `write_angles`
→ 机械臂内部不再"分段启停"。

### (g) 让 hardware interface 用流式 API

如果固件支持，可以把 `cmd_publish_rate` 推到 100 Hz（== update_rate），
让机械臂真正连续插值。
关键点：`write()` 里别做 I/O，只更新 `pending_cmd_`，
由独立 timer 线程把命令发出（当前代码已是这种结构，只缺频率）。

---

## 验证方法

改完后，重新启动 move_group + 真机，跑：

```bash
ros2 launch moveit2_ompl_demo ompl_planner.launch.py \
    goal_x:=0.2 goal_y:=0.2 goal_z:=0.1 position_only:=true
```

观察：
- 抖动是否消失（末端执行时是否平稳）
- 卡顿是否消失（运动是否连续无停顿）
- 规划时间是否仍 <1s（Ruckig 可能略增 0.1~0.5s）
